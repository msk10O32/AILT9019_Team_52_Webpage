Why this exists

AI answers about university rules can sound convincing while being wrong, outdated or unsupported. The prototype is deliberately narrow so that the evidence can be checked.

The problem

Students ask chatbots about add/drop dates, course credits and programme rules. The answer is fluent, but it may not match the official page and usually gives no citation.

Who it is for

HKU students who want to check an AI-generated answer before acting on it. Scope: academic year 2026-27 and the BEng Computer Science programme.

What it does not do

It does not decide personal eligibility, credit transfer, enrolment or graduation. Subjective and personal-eligibility claims are reported as not covered.

How it works

The model does the language work. Retrieval and evidence validation stay local, deterministic and reproducible.

  1. Paste an answer. The local web UI sends it to the local server as a background job.
  2. Split into claims. The course model uses a fixed JSON prompt; a deterministic sentence splitter is the fallback if the call fails.
  3. Retrieve evidence. A local BM25 index searches 274 passages from three saved official HKU snapshots and returns the best-matching passages for each claim.
  4. Compare. The model receives one claim and its passages and must return a JSON verdict with a reason and evidence.
  5. Validate evidence. Our code checks that the passage id was retrieved and the quote exists verbatim in the saved source; failures become not covered.

What we built, what the model does

The model supplies two language steps. Everything around it is team code, tested locally.

Team-built, local

  • Corpus pipeline: fetch, clean, chunk and snapshot official pages, including PDF text extraction.
  • Local BM25 index over the saved passages, with top-4 retrieval per claim.
  • Quote and passage-id validator; fabricated citations downgrade to not covered.
  • Out-of-scope handling for subjective and personal-eligibility claims.
  • Local web interface, server, trusted-source manager, offline replay and 138 automated tests.
  • Read-only pre-start check that compares live page hashes with the committed snapshot.

Course model / API

  • Splits an answer into atomic claims with a fixed JSON prompt.
  • Compares one claim with the passages retrieved for it.
  • Returns a JSON verdict, reason and quoted evidence.

No fine-tuning, no embedding model and no live web search at check time. The model never sees the whole corpus; it only sees the passages selected for one claim.

Domain customisation

The corpus is a versioned snapshot of three official HKU sources, not a generic web index.

SourceWhat it coversSnapshot
Important Academic Dates 2026-27 (AAS) Semester dates, add/drop periods, assessment periods and deadlines. 24 Oct 2026
Regulations for First Degree Curricula (HKU Calendar) University regulations that apply across degree curricula. 24 Oct 2026
BEng(CompSc) Regulations & Syllabus 2026-27 Programme requirements, course codes, credits and course descriptions. 24 Oct 2026

What we customised: course-code, month and add/drop normalisation; a three-verdict schema including not covered; and versioned snapshots with URL, retrieval date and SHA-256.

274 passages in total. The prototype is English-only: the corpus is English and the tokenizer indexes Latin words and numbers.

Limitations and failure cases

The system is intentionally narrow. Known gaps are stated instead of hidden.

Known limitations

  • English only. The corpus is English and the BM25 tokenizer indexes Latin words and numbers; non-English claims retrieve no passages and are reported as not covered.
  • Lexical retrieval. Synonyms and paraphrases can produce a false not covered. We prefer an honest refusal over a guess.
  • Snapshots can age. Pages may change after the snapshot date. The launcher checks for updates before the server starts; rebuilding the snapshot is a separate, explicit step.
  • The model can still be wrong. Quote checking proves the quoted text exists, not that the verdict is correct.

A failure mode we expect

A claim that says students can withdraw from a course after the second week uses “withdraw”, while the official page uses add/drop period. BM25 does not know those terms are related, so it may miss the rule and the claim comes back as not covered.

That is a lexical-retrieval false negative, not a model answer. The app prefers an honest refusal to a guess.

Run it locally

Python 3.10 or newer. No pip install: the app only uses the standard library and a local browser UI.

git clone https://github.com/msk10O32/AILT9019_Team_52
cd AILT9019_Team_52
python app.py

Open http://127.0.0.1:8765/. On Windows you can double-click run.bat; on macOS or Linux run ./run.sh. The launchers check the official pages for updates before starting and then start the app either way.

Add a key, or use the demo

Paste an OpenAI-compatible API key in API settings, then press Check answer. Without a key, the Load demo answer button replays the recorded run.
